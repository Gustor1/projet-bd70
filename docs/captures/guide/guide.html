Captures réalisées le 7 novembre 2026 sur la version corrigée (historisation, indicateur HAVING, planification réservée au responsable), sur une base de test neuve. Les références ORAL-CAFE et les noms affichés proviennent du jeu de test (graine 70) : ils peuvent différer légèrement sur le jeu riche de démonstration.

Sommaire

  1. A · Préparer le poste : prérequis, comptes, conseils.
  2. B · Démarrer et arrêter l’application : commandes PowerShell et résultats attendus.

Convention : PS> = commande à taper dans PowerShell. Un bloc gris clair = ce qui doit s’afficher. Un cadre orange sur une capture = l’élément sur lequel cliquer.

A · Préparer le poste

  • XAMPP installé dans C:\xampp2 (MariaDB 10.4 dans C:\xampp2\mysql\bin, PHP 8.2 dans C:\xampp2\php). Ailleurs : ajouter -PhpPath et -MariaPath à la commande de démarrage.
  • Le projet dans C:\Users\eliot\Documents\GitHub\projet-bd70, avec config/local.php (créé à la première installation, jamais dans Git).
  • Un navigateur récent (Edge ou Chrome). Pour la démo, préparer un profil de navigateur par compte : deux onglets d’un même profil partagent la session.
  • Python et Node ne servent qu’aux tests automatisés et à la reconstruction des documents, pas à l’application.

B · Démarrer et arrêter l’application

B1. Ouvrir PowerShell à la racine du projet

Set-Location "C:\Users\eliot\Documents\GitHub\projet-bd70"

B2. Démarrer MariaDB et le serveur PHP

powershell -ExecutionPolicy Bypass -File scripts/start.ps1

Premier lancement après les corrections : la base de démonstration reçoit les objets d’historisation (aucune donnée modifiée).

Historisation ajoutée à bd70_demo_corrige_20261103b : appointment_archive, v_appointment_all, 2 triggers, archive_appointments, ev_archive_appointments.
Pour exécuter l'évènement automatiquement : SET GLOBAL event_scheduler=ON (compte administrateur).
Application : http://127.0.0.1:8070

Lancements suivants :

Historisation déjà installée dans bd70_demo_corrige_20261103b.
Application : http://127.0.0.1:8070

B3. Ouvrir l’application

Aller sur http://127.0.0.1:8070. La page de connexion s’affiche.

B4. Arrêter

powershell -ExecutionPolicy Bypass -File scripts/stop.ps1
En cas de problème.
• « MariaDB introuvable » : ajouter -MariaPath "chemin\mysql\bin".
• « Port occupé par un autre serveur » : arrêter l’autre MariaDB, ou lancer avec -DbPort 3308.
• « Migration de l’historisation échouée » : lire le message au-dessus ; la base n’est pas modifiée si la migration échoue avant la création des objets.
• Page blanche ou erreur PHP : consulter .local/php-error.log.

B5. Base de répétition (pour refaire le scénario E sans toucher à la démo)

MariaDB doit tourner (étape B2). Choisir un nom de base jamais utilisé, puis, dans une nouvelle fenêtre PowerShell à la racine du projet :

$env:BD70_PORT='3307'; $env:BD70_DATABASE='bd70_test_repetition_01'
& C:/xampp2/php/php.exe scripts/install.php $env:BD70_DATABASE

$env:BD70_NOW='2026-10-22 12:00:00'; & C:/xampp2/php/php.exe -S 127.0.0.1:18079 -t public

Ouvrir http://127.0.0.1:18079 et garder la fenêtre ouverte. BD70_NOW fixe la date au 22/10/2026 pour que les DLC et le FEFO soient reproductibles. Fermer la fenêtre arrête ce serveur ; la démo du port 8070 n’est pas touchée.

D · Vérifier les nouveautés dans l’application

D1. Le responsable planifie les quais

Se connecter avec manager@bd70.test → menu Quais & rendez-vous → choisir la journée → le bouton Nouveau rendez-vous est visible. Avec gate@bd70.test, le même écran s’affiche en consultation, sans ce bouton : le sujet réserve la planification au responsable, l’accueil tient le poste de garde.

D2. Créer un rendez-vous

Avec le responsable, cliquer sur Nouveau rendez-vous. Remplir : Référence VERIF-01, un quai, un chauffeur et un véhicule compatibles, l’opération, un début et une fin sur un créneau libre (ici le 24/10/2026 de 07:00 à 07:30). Cliquer sur Enregistrer.

D3. Refus du chevauchement

Refaire exactement la même saisie avec la référence VERIF-02. Le refus s’affiche ; la base le refuserait aussi par trigger (partie C). Ensuite, dans le planning, annuler VERIF-01 pour garder la démo propre.

D4. Indicateur avec HAVING

Se connecter avec manager@bd70.test → Indicateurs & états → choisir la période et un Seuil d’attente (min) → Filtrer. Sur le jeu riche : période 01/08/2026 – 29/10/2026, seuil 8 = les transporteurs apparaissent ; seuil 20 = tableau vide.

D5. Rendez-vous historisés

Toujours en responsable → Référentiels → rubrique Rendez-vous historisés → Afficher. Lecture seule : aucun bouton de modification. Sur la démo, la liste est vide tant que l’évènement n’a rien archivé (rendez-vous de plus d’un an).

D6. Transporteur limité à sa société

Se connecter avec carrier1@bd70.test : seuls ses rendez-vous apparaissent ; il peut en demander, modifier ou annuler.

E · Scénario complet ORAL-CAFE

Ce parcours suit un lot de café de bout en bout : le fournisseur annonce 20 unités, le magasinier en accepte 18 et en déclare 2 endommagées, transfère 3 unités, puis 10 unités sont préparées en FEFO, mises en colis et chargées dans le camion ORAL-CAFE-SORTIE ; la traçabilité retrouve ce camion à partir du lot.

Où le faire ? Sur la base de répétition (B5, http://127.0.0.1:18079) pour refaire les saisies. Pour l’oral, montrer les fiches déjà créées (rechercher ORAL-CAFE dans chaque écran) plutôt que tout saisir en direct. Chaque étape indique le compte à utiliser : se déconnecter (en haut à droite) puis se reconnecter, ou utiliser un profil de navigateur par compte.
